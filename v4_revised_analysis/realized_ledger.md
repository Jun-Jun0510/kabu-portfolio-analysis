## なぜこのファイルが要るのか

**証券アプリの「評価損益」は、今持っている銘柄だけの数字。売った銘柄は最初から入っていない。**

| | 米国株評価額 | 評価損益（画面表示） |
|---|---|---|
| **2026/10/20 現在** | 785,105円 | **−33,950円（−4.15%）** |
| **OKLOを売った直後** | 740,829円 | **+48,921円（+7.07%）** |
| CBRSも売った場合 | 700,555円 | **+82,081円（+13.27%）** |

**資産は1円も増えていない。損はもう発生済みで、売却は未実現を実現に変えるだけ。**
**それでも画面は +11.2ポイント改善する。**

> **総資産画面の「+323,298円（+7.84%）」も同じ構造。売るたびに自動的に見栄えが良くなる。**

### これは §32 の調査とまっすぐつながっている

**Bessembinder (2018)**: 生涯でT-billに勝つ銘柄は **42.6%**。**中央値はマイナス**。

> **負ける銘柄のほうが多い分布で、負けた銘柄だけが画面から消える仕組みを使っていると、
> ダッシュボードは構造的に実態より良く見える。しかも売れば売るほど良く見える。**

そして実害は既に出ている:
- **OKLOは −4%（4月）から −56%（9月）まで5ヶ月間、一度も検証されなかった**（§3）
- **「売却完了」と記録してから1ヶ月、現物が確認されなかった**（§30）

**画面がフィードバック装置だったのに、一番学ぶべき失敗を消す設計になっている。**


## 2. 対照 — **売って正解だったかを後から検証する**

**これが無いと「売らなければよかった」も「売って正解だった」も永遠に分からない。**

2つの別の問いがあるので、分けて記録する。

## 3. 真の成績の測り方 — **評価損益は成績ではない**

**画面の評価損益は、売った銘柄を含まないので成績ではない。**

```
真の成績 = 現在の総資産 − 入金総額（元本の累計）
```

これなら売った銘柄も、実現損も、全部入る。**生存バイアスが入り込む余地がない。**

| 項目 | 値 | 状態 |
|---|---|---|
| **入金総額（累計）** | **要確認** | ⚠ 記録が無い。**楽天証券の入出金履歴で確定させる** |
| 参考: 2026年4〜8月の入金 | 約 1,124,490円（3.7ヶ月 / 月約304,000円） | 記録あり |
| 現在の総資産（2026/10/20 23:19） | **4,443,155円** | 確定 |
| **真の成績** | **（上が埋まれば計算できる）** | |

> ⚠ **画面の「+323,298円（+7.84%）」は真の成績ではない。** 保有中の銘柄の評価損益であり、
> **PAYP・RXRX・EWYの実現損 −3,767円 は最初から入っていない。** OKLOを売れば −82,871円 も消える。

## 4. 運用ルール

### 書くタイミング

| いつ | 何を書くか |
|---|---|
| **売却を決めた時点（約定前）** | 🔴 **取得価額・評価損益・売却理由・判定日**。**約定後では取得価額が画面から消える** |
| **約定後** | 売却日・売却額・**売却日の株価**・**売却日のオルカン基準価額**・口座区分 |
| **四半期レビュー（`review_sheet.md` 手順0）** | 売却済み銘柄の**その後の株価**を1行書き足す（問Bの検証） |
| 年1回（12月） | 入金総額を更新し、**真の成績**を計算する |

### 原則

1. **「判定日」と「約定日」を必ず分ける**（§7の2026/10/19追加ルールと同じ。§30で1ヶ月のずれが生じた）
2. **実現損は消さない。** 金額が小さくても残す（PAYP −1,153円も記録対象）
3. **成績を語るときは、画面の評価損益ではなく「総資産 − 入金総額」を使う**
4. **売却後も追跡をやめない。** 問Bの検証ができなくなる
